# 登录同步 · Apple 风格界面设计

2026-11-05 完成的可交互源设计稿。依据已确认的[流程需求](../../specs/cookie-extension-simplified-flow.md)，采用原生 HTML/CSS/JavaScript，无外部依赖。

## 打开方式

- 双击同目录的 `index.html` 即可查看；保留 `styles.css` 与 `app.js` 在同一目录。
- 本机预览：`http://127.0.0.1:4179`。
- 如果预览服务未运行，在此目录执行 `node serve.mjs`。服务仅绑定本机回环地址，只提供三个设计文件。
- 顶部“预览场景”切换首页、首次使用、授权、错误、升级等场景。弹窗内可以继续操作，Esc 可关闭。
- 配对演示使用底部“填入示例配对码”。旧版单平台演示码为 `LEGACY-DEMO-JD`。
- 页面记住示例地址和设置；选择任何预览场景会重新载入对应的示例状态。

## 设计交付

视觉采用浅银灰背景、白色圆角面板、柔和蓝色、轻微玻璃模糊及细线图标。首页保留一个后台连接条、角色卡和主要同步操作，详情收进弹窗。

| 页面/状态 | 主要交互 |
| --- | --- |
| 同步首页 | 角色、平台状态、同步、管理平台；只有待处理项提供补救按钮 |
| 首次使用 | 一次保存后台地址 → 两种授权入口 |
| 绑定后台 | 配对信息 → 默认不勾选的平台选择 → 集中确认脱敏账号 |
| 反向授权 | 选择平台 → 等待批准 → 后台审批示意 → 明确目标角色 → 首次确认 |
| 同步结果 | 各平台独立结果；“等待采集验证”和“后台已验证”分开显示 |
| 补充登录 | 进入平台登录示意 → 返回原角色 → 首次账号核对 → 继续同步 |
| 管理平台 | 本次平台选择与后续自动同步分开；保存或取消；保留旧配置 |
| 异常状态 | 离线、权限缺失、账号不匹配、授权失效、申请过期有各自处理入口 |
| 多个后台/旧版授权 | 按后台隔离角色；单平台配对仅显示原权限范围 |
| 设置 | 后台地址、浏览器名称、诊断、版本升级；角色更多操作中撤销授权 |
| 本地升级 | 当前版/示例目标版 → 原安装目录 → 校验备份覆盖示意 → 重载保留设置 |

## 浏览器验证记录

使用本机 gstack Chromium 验证，未访问真实平台或真实后台。

- `node --check app.js`、`node --check serve.mjs` 通过。
- 桌面 1440px 与窄屏 390px 已查看截图；390px 页面 `scrollWidth` 为 390，无横向溢出。
- 配对流程首次不预选平台，未选择时不能继续；两项可同步、一项待登录的结果正确。
- 拼多多补充登录回到原角色，首次核对后显示三个平台已同步、等待采集验证。
- 反向申请可以包含未登录的平台；刷新后保留待批准申请；后台明确选择角色后再确认账号。
- 管理平台关闭京东后，其自动同步开关禁用，刷新后平台选择仍保留。
- 后台地址格式错误显示就地提示；示例地址保存、刷新回显正常。
- 离线保留角色与历史状态；权限缺失、账号冲突分别进入对应补救状态。
- 多后台切换显示各自角色，旧版单平台授权只显示京东。
- 本地更新流程可点击至覆盖确认和重新加载，角色与平台选择保留。
- 弹窗内 Tab/Shift+Tab 保持焦点，Esc 关闭并将焦点交回原入口。
- 检查浏览器控制台无错误。

## 交付边界

这是完整界面与流程原型，所有账号、连接、审批、同步与升级均为示例。不会读取 Cookie，不连接后台，不修改已安装插件，不执行文件覆盖。`1.2.0` 是升级界面的示例目标版本，不代表已发布。生产插件继续保持现有版本。

本次没有发布到仓库、修改后台或部署服务。源视觉稿确认后，按项目既定流程进入 Figma 和正式插件实现；本文件不代表视觉审批。
