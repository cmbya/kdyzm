## 视觉与可读性

沿用参考图的银灰底、真实磨砂卡片、钴蓝主操作、青绿柜号块和系统字体。卡片、列表、工具栏、分段选择器与底栏都应看见背景色层经过模糊后的透入，不能以接近实白的填充代替磨砂。参考图顶部的方案编号、装饰线不进入产品。

B 版源稿采用约 50% → 34% → 42% 的浅白半透明渐变、26px 背景模糊与 104% 饱和度；底栏模糊为 28px。白边透明度 88%，顶内光 90%、底内光 25%，外阴影为 0 12px 30px rgba(61,78,105,.08)。全部共用玻璃变量，避免不同页面材质漂移。银灰底需要克制的深浅层次及不可喧宾夺主的极细噪点；噪点不是正文上的纹理。正文文字保持不透明，柜号色块与主按钮保留清晰实色。文字不够清楚时优先加深文字或调整局部背景，不能把全部玻璃面改回实白。

不支持标准及前缀背景模糊的环境才使用实色回退；回退须覆盖卡片、列表、工具栏、分段器、站点标题、弹层和底栏。支持前缀模糊的环境仍应保留磨砂。回退保留相同尺寸、描边、圆角和信息层级，不使用透底但未模糊的背景影响正文可读性。

## 固定槽位与字段去重

取件卡结构固定：顶行“归属 + 平台”、右上菜单；下方左侧柜号；右侧首行取件码独占可用宽度；商品、时间、来源各占固定行；主取件按钮靠右。标准卡高由统一行高决定，约 172–184px，不能逐卡自由压缩。

- 商品名约 9–10 个汉字，单行省略；完整名称进入详情。缺少商品名、时间或来源时保留对应行高，不上移后续字段，也不填充“暂无”等噪声文案。
- 取件码、柜号不得省略关键字符。长取件码先采用较小但可读字号，必要时换行并使用统一的扩展卡片规格；不能让按钮挤压或遮挡取件码。
- 平台已出现时，删除重复的“线上订单”文本；来源槽位保持。只有独立且有用的来源信息才显示。
- 站点只显示在分组标题，不在组内每张卡重复。原始短信/原文、订单号、运单号、完整物流轨迹进入详情。
- “待归属”与“未关联订单”是不同状态，不能互相替代。顶行优先显示当前需要处理的一项，另一项由详情或次操作表达，避免同时堆两枚近义视觉标签。
- “匹配订单”使用弱描边或文字次操作；领取与匹配彼此独立，未匹配不阻止领取，不强迫用户先匹配。
- 每个页面只保留一个主标题，不增加解释性副标题；全局同步只保留一个入口，不在各页重复创建同义动作。

## 业务语义必须保持

| 概念或动作 | 源稿必须表达的边界 |
| --- | --- |
| 领取 | 用户从站点/柜机取走包裹的应用内状态；多件共码按成员记录领取，不能一按就让全部成员领取。 |
| 物流签收 | 物流数据中的节点或状态，不自动等同于用户本人已取到。 |
| 确认收到 | 应用内收货记录，区别于购物平台的“确认收货”；设计中的确认或自动归档不向购物平台执行操作。 |
| 通知关闭 | 右侧关闭仅处理通知显示，不代表领取、匹配、签收等业务已完成。 |
| 解除关联 | 保留原取件码、包裹和领取状态；不得自动重新关联。 |
| 30 天归档 | 按现有条件处理：已签收记录归档时自动确认收到；未签收记录仅归档且可恢复；不得冒充购物平台操作。 |
| 包裹统计 | 现有 `all` 实际含义是“未收到”，包含待发货、运输、待取；界面文案不得称其为全部包裹。手动记录单列“其他”。 |
| 过期统计 | 按订单数显示；订单、包裹、取件码数量不得混用单位。 |

## 自动化与规则页面的信息组织

`auto-settings` 可拆为自动监测摘要、短信扫描与权限、站点片段增强、人工纠错提交回执、桌面卡片五组导航；桌面卡片覆盖 2×2、4×2、5×3。该拆分仅为导航建议，沿用现有能力边界。

- 短信 AI 结果是待确认建议；用户确认保存后才成为规则或记录。不得用成功外观跳过确认。
- AI 不可用不影响手动规则的查看、编辑和保存。物流规则仅在本地生效，不能宣传云同步或跨设备生效。
- 人工修正记录与提交回执如实标注为人工行为；不得包装成 AI 自动运行日志、训练成功或自动处理证据。没有真实数据的演示回执须明确为源稿示例。
- 账号核验要求家人或指定账号授权，并显示失效日期；授权失败、失效、撤销与待核验状态须可区分，不能把登录成功当作授权完成。

## 最终设计验收清单

- 14 条现有路由有设计映射；新增拆分页标明对应原路由；完整场景逐项纳入主代理矩阵。
- 360 / 390 / 430px均无横向溢出；主按钮、右上菜单、字段槽位对齐；列表末项可完整滚动到安全区上方。
- 有/无商品、有/无柜号、有/无订单、长取件码、长站点名、多件共码都有覆盖；缺失数据不造成关键行跳位。
- 领取、匹配、解除关联、关闭通知、签收和确认收到的结果符合上表，所有数量单位明确。
- 加载、空态、错误、禁用、权限拒绝、授权失效、AI 不可用、待确认及完成回执可辨识，且允许合理恢复。
- 列表、详情、编辑、规则、账号、帮助与弹层共享颜色、字级、圆角、按钮和图标语言；不新增另一套视觉风格。
- 支持模糊时可见真实磨砂透色、细高光与柔和背景层次；不支持时稳定回退实色。小字在玻璃最暗处仍达到目标对比。
- 纯色对比值仅是回退基线；实施后验收真实文本背景、系统字体缩放、触控区域和读屏名称。
- 用户确认源稿后再进入 Figma；Figma 对齐后实施；最终以实际运行界面的交互和业务状态验证收口。源稿验收不等于 App 验收。
