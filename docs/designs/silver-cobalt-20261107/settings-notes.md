# 设置与识别优化设计场景

此文件与 `settings.js` 仅用于银灰 / 钴蓝设计预览，不修改正式 Vue 页面，不连接服务，不操作短信、授权、规则或更新安装。账号、时间、数量与短信均为合成内容；当前版本统一为 3.1.33，未来更新 3.1.34 明确标注“示例”。新增子页面是信息架构建议，`route` 元数据指出现有来源。

## 不能改变的边界

- 短信 AI 是自动准备候选，手机确认使用后才保存；没有成功率、准确率、通用 AI 运行日志。
- AI 默认服务、模型、密钥和后台调优策略归后台；手机只显示服务与处理结果。后台策略可能返回 applied/review，不统一宣传为全部人工或全部自动。
- AI 监测词调优仅为无箭头的只读状态，不链接自动领取结果。完整 AI 运行日志是现有手机数据能力缺口，本稿不虚构新日志数据。
- 人工修正已保存、样本已提交、后台处理、手机规则导入回执是不同阶段；回执不证明识别效果。
- 领取监测只认明确本人/收件人领取；代收、门口、泛签收不计入。自动完成记录不是 AI 分析记录。
- 本机物流规则不上传也不修改后台物流规则；到站事件和仅位置提取不能混同。
- 删短信规则保留既有记录；物流恢复默认会删除本机手动规则，必须保留确认。
- 绑定前核验地址与授权范围；家人组包含以后新增账号，指定账号不扩大授权；解绑/换服务保留本地历史。
- 关闭更新弹层不等于取消下载；系统安装器已打开不等于安装成功。
- 隐私模式同时覆盖取件码、柜号、公司、地址及相关详情。桌面预览中的文案不代表已执行取件。
- 关于与 FAQ 不再沿用“直接向 DeepSeek 上传当前样例及正确码”的旧文案；当前口径为后台统一服务 + 合成模板片段。

## 共用交互与剩余呈现

按钮目标是本地设计场景；`data-demo` 操作仅提示后续真实流程。应由主稿统一提供确认反馈、键盘焦点、滚动、系统引导和空/加载/错误样式；这里不接生产行为。

权限拒绝、AI 服务未配置、修正提交失败已拆成独立可打开场景，不用教学说明代替状态。正式实现时保留 AI 开启/暂停清除、站名上传开启、删规则、恢复默认、换服务、解绑等现有确认弹窗；本设计模块没有删除这些需求。

CSS 仅复用主稿类及 U helpers。连续 row/toggle/kv 放入 `.list` 卡片；普通柜号标签使用 `.hero-cabinet`，不复用取件卡的大柜号容器。磨砂、模糊与配色由主代理统一修改，本模块不写 CSS 或新 token。

## Modern Web Guidance

- `forms`：我保留可见字段标签并为手写 textarea 建立 for/id 关联，遵循 “DO use visible labels; do not rely on placeholder alone”。
- `accessibility`：我用原生 button、details/summary 和 progress 表达操作/展开/进度，没有给静态卡片伪造按钮角色；遵循 “Prefer HTML elements and attributes to ARIA”。

验证由本轮最终检查确认：`node --check settings.js`；Node VM 加载真实 `ui.js` 与 `settings.js`，断言 33 个唯一场景、全部 content/footer 可生成、全部 data-go/back/top 目标存在、手写 textarea 的可见标签关联完整，并检查三个尺寸导航及版本口径。

未检查：浏览器布局、屏幕阅读器、真机与生产服务；系统权限/同步/安装按钮仅为设计演示。浏览器验证由主稿统一进行。
