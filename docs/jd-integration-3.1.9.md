# 京东买家订单接入 · 服务端3.1.9

2026-11-01 使用本人正常登录的京东PC买家会话，在浏览器与独立 Node 24.13.0 进程中验证订单、运单和物流。使用普通登录 Cookie，不需要浏览器worker、动态签名、设备令牌、页面UUID或详情PassKey；没有新增依赖。

## 使用

升级服务端后，在家人工作台添加平台“京东”，填写账号名称及本人订单页的完整 Cookie（含 `thor`），保存后点击立即采集。只含手机 `pt_key` 的凭证未验证，不作为本次支持入口。原有家人整组授权持续包含新增京东账号，既有设备无需重新绑定。

Cookie仍通过现有AES-256-GCM加密，不返回App或管理账号列表。登录失效会提示更新Cookie，保留已有订单。不要把凭证发到聊天、Issue、截图或Git。此次验证所用的凭证和真实响应仅在仓库外受限临时目录中处理，不作为演示数据或测试fixture。

App现有快照协议可承载 `platform=jd`，取件、包裹、家人分组和大组件沿用现有数据路径。配套App源码补充线上账号页的京东名称及图标；本次服务端更新不要求重新绑定设备。

## 接口与采集规则

| 用途 | 实测接口 | 参数 |
| --- | --- | --- |
| 订单列表 | `POST https://api.m.jd.com/api`，`appid=order-jd-com`，`functionId=pcorder_center_list` | 表单 `body` 为 `{page,d:1,s:4096}`，近3个月全部订单 |
| 单笔物流 | 同一入口，`appid=details-jd-com`，`functionId=pcdetail_traceMultiPackage` | URL参数 `body` 为 `{orderId}`，无需其他详情字段 |

请求固定使用HTTPS与主机白名单、20秒超时、5MiB响应限制，拒绝重定向。401或HTTP200的 `{code:3}` 表示登录失效；403表示平台拒绝访问。未返回约定结构时保留历史并报告错误，原始响应不回显给用户。

- 列表下单日期 `dateSubmit` 与金额 `itemPayInfo.shouldPay` 直接映射，金额单位为元。子订单按自己的 `orderId` 去重，不把父单金额重复导入。
- 仅新发现的明确待发货、待收货实物订单进入记录；已完成、已取消、未付款及识别到的服务/虚拟商品仅更新已有历史。当前验证的服务类型4、虚拟类型69以及全虚拟商品单不导入。
- 待发货无运单也保留订单。物流以每个包裹的 `carriageInfo.carriageId` 和 `carrier` 匹配，轨迹来自 `orderTrackShowList`。取件码仅使用包裹自己的字段或当前节点，不把一个码复制给其他包裹。
- 详情 `processTimeInfo.submitDate` 可含字面量 `<br/>`，规范化后作为详情日期；缺失或失败不覆盖可信列表日期。
- 签收仅更新物流状态，不自动改变助手已取、隐藏、删除或人工日期。空轨迹不降级已有到站状态；列表缺席和分页上限不代表删除或领取。
- 每轮最多5页、20笔详情；已有活跃运单和无码订单按最近补查时间轮转。已手动完成的运单不会占用常规详情预算；用户主动刷新单笔时只查询目标订单。

## 验证与边界

真实 Node 最小请求仅使用当前PC Cookie、固定UA、Origin/Referer和业务参数。去掉捕获请求中的 `h5st`、`x-api-eid-token`、`uuid` 并重新生成时间参数后，列表返回20笔；物流仅传orderId，返回1包裹及15轨迹。未登录响应确认为HTTP200 `{code:3}`。

最终采集器真实验证：当前样本均已完成，全账号首次采集不导入这些旧订单，返回20条历史元数据更新；对指定实体订单刷新获得1个已签收运单、15条轨迹及可信下单日期，不产生人工已取标记。

模拟回归另覆盖待发货、运输中、拆包、无码、服务/虚拟过滤、分页重复、详情预算轮转、空日期/空物流、登录失效、家人未来账号授权、凭证加密与人工状态保护。当前账号没有待发货、运输中或待取实物样本，这些状态和真实取件码尚未完成账号实测；长期登录有效期与NAS出口环境也需后续运行确认。本次不是官方公开API稳定性承诺。

服务端与App版本独立。镜像经CI测试及容器验收后发布；已有NAS容器需重新拉取并重建，保留原数据卷和密钥。此次开发未修改NAS生产数据或替用户创建真实账号。
