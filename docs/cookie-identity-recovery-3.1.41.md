# 后台 3.1.41：登录同步恢复

淘宝网页已登录，但插件仍提示账号不一致时，可能是后台保存的登录信息已丢失账号标识。已确认当前故障数据属于标识缺失；用合成平台响应复现了登录失效响应清空标识后，同账号被拒绝的路径。未捕获此次真实平台响应，不能断言标识丢失的唯一来源。

本版阻止采集中的 Cookie 轮换删除、替换或混入冲突的已知账号身份；缺少登录字段也会停止采集并保留原凭据。正常的令牌轮换继续保存，旧版手动录入但没有身份字段的凭据保持兼容。最终返回的轮换凭据在导入订单之前校验，避免跨账号数据导入。

已损坏的历史凭据不会自动猜测修复。后台会让插件显示“后台原登录信息的账号标识异常，请管理员核对后重新配对”，真正不同账号仍显示账号不一致。插件 1.2.0 已支持这条提示，无需更新插件或 App 3.1.44。

## 已出现问题的账号如何恢复

1. 将后台更新到 `ghcr.io/zsdd2/kdyzm:3.1.41`，保留原数据卷和加密密钥。
2. 浏览器打开淘宝订单页，确认登录的是原账号。
3. 后台“账号授权”选中原角色，在“插件同步授权”重新生成配对信息；插件“添加授权 → 绑定后台”粘贴，选择淘宝并完成首次账号核对和同步。旧单账号授权也可在原账号详情中重新生成配对信息。
4. 角色重新配对会替换该角色的旧插件授权；如同时使用京东、拼多多，在新的授权中重新选择需要同步的平台。

无需删除账号、角色或订单，不修改设备授权。只重新同步登录信息；登录成功与平台允许自动采集是不同条件，平台风控仍可能要求稍后重试。

## 验证范围

回归覆盖真实采集调用链中的合成失效响应、同账号恢复、非法轮换中止、正常令牌轮换、历史污染后的明确重新授权，以及跨账号拒绝、凭据并发版本保护。真实浏览器插件的最终重新授权由用户更新后台后操作，本轮没有改写生产凭据或更新 NAS。
