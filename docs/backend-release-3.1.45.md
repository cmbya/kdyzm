# 后台 3.1.45

修复淘宝发货时间漏读，新增独立只读诊断 API。App 保持 3.1.46 / 30146，Chrome 插件保持 1.2.1，本轮只需更新后台。

## 淘宝时间修复

- 明确的“已发货”与“等待揽收”可以同时成立，不再丢弃对应发货时间。裸“等待揽收”、预计、失败、退回和改派仍不能充当发货证据。
- 对缺少年份的发货、下单和仓库处理节点，仅在已核实的订单详情日期至采集时间区间内年份唯一时补全年份，并保留分钟精度；不借用另一运单的时间。
- 签收、取件、到站、退回、改派及歧义时间不使用上述推导。未知保持未知，人工取件决定保持有效。
- 升级提取缓存版本，下次正常采集会重新计算旧错误；仅打开页面或读取诊断 API 不会修改订单。

## 后续如何通过 API 调试

升级后在后台“服务设置 → 基础设置 → 只读诊断 API”创建并保存一份凭据。完整凭据只显示一次，数据库仅保存摘要；凭据不自动过期、重启后仍有效，管理员可单独撤销。管理员网页登录会话不再是日常诊断的前提。

脚本以 Bearer 凭据直接调用订单查询、物流详情、账号采集状态、异常重试任务和每日复盘接口。接口严格只读，不返回平台 Cookie、管理员密码或 AI 密钥，不触发采集或 AI。配置、字段、分页和调用示例见[诊断 API 文档](diagnostic-api.md)。

- 查询已有字段、复核真实数据和定位同类问题：无需每次更新后台，直接调用 API。
- 调整已有识别规则：使用现有规则配置与校验流程；诊断凭据没有写入权限。
- 修复采集程序、改变时间解析逻辑或增加 API 能力：仍需发布并更新后台。涉及手机或插件代码时才更新对应端。

## 手动升级

拉取 `ghcr.io/zsdd2/kdyzm:3.1.45` 或 `ghcr.io/zsdd2/kdyzm:latest`，保留原数据卷、加密密钥和配置重建容器。无需清库、卸载 App 或重新绑定。已有 App 3.1.46 和插件 1.2.1 可继续使用；镜像继续内置同一 App 升级包，GitHub Latest Release 保持 App 3.1.46。

NAS 更新由使用者手动执行。升级并配置诊断凭据后，先检查 `GET /v1/diagnostics/status` 返回后台 3.1.45，再在下一次正常采集后核对具体订单时间。

## 验证边界

发布核对完整七项开发门禁、发行仓测试、生产依赖审计、容器存储/重启验收、双架构镜像版本及内置 App 包一致性。回归包含发货等待揽收、跨运单隔离、缺年份边界、完成语义排除、旧缓存重算、诊断凭据重启保留/撤销/权限隔离，以及退出登录后清除凭据显示。

未代为更新 NAS、配置生产诊断凭据或执行生产 AI 调用，线上具体订单效果需升级并重新采集后确认。本地 nightly/Semgrep 和实体手机安装未执行。
