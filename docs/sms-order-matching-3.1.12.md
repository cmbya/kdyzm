# 短信与平台包裹的关联

服务端3.1.12，配套App3.1.15。实现依据为已确认的时间与站点匹配方案。

平台没有取件码时，App仍可把短信与订单关联：先精确核对运单号，其次沿用原取件码规则，再检查真实末端到站时间和取件站点。时间差不超过60秒，且短信与运单双方只有一个候选时自动合并。站点缺失不阻止唯一时间匹配；站点明确不同则排除。只有分钟精度的数据只在同一分钟自动匹配。只有站点一致时提供推荐，需人工确认。

同一运单的多条轨迹先去重。同分钟多个包裹、多个家人的候选，或多条短信竞争一个运单时不任选第一条。发送时间缺失时使用收件时间，补录发送时间不改变历史短信身份。同步时间、普通柜机记录创建时间、转运中心和“下一站”计划不是末端到站证据；退回改投后清除旧周期关系，保留原短信以便核对。

首页未关联短信条目提供“匹配订单”。详情弹层可选推荐候选，也可查看其他未完成包裹，搜索商品、订单号或运单号，按家人和平台筛选。每行包含商品、家人、平台、站点、运单尾号、到站时间及时间差。已有明确差异时先提示确认。无有效运单号、已隐藏、已归档、已人工领取或超出当前授权的包裹不可新关联。

关联按具体运单成员保存，一单多包不整单绑定。多件短信可选择不超过原件数的成员，未分配成员继续占位；此前匿名部分领取的数量继续保留，明确对应后才上传实际领取操作。单件已取短信绑定到共码组时，只同步明确选中的运单，不能带动同组其他包裹。

可解除单件或整条短信的关联，保留短信、订单与人工领取状态，之后同步不自动连回。主动重新匹配为原子操作，失败保留原关系和选择。后续补出竞争候选会提示核对；核对前，首页、记录页和原生组件不能绕过详情直接领取。确认当前或新的选择后作为人工结果保留。

关联关系保存在当前手机，包裹记录和桌面组件读取同一份关系。不会把短信正文、取件码或关联关系上传服务端；确认领取仍复用既有助手操作，不向电商平台确认收货。跨手机共享关联不在本次范围。

先拉取并重建后台 `ghcr.io/zsdd2/kdyzm:latest`，保留原数据卷、密钥和家人授权，再覆盖安装App3.1.15并立即同步。无需重新绑定。旧客户端仍能读取旧字段；新关联需新版App与真实到站来源证据。升级后重新检查已有未关联待取短信。
