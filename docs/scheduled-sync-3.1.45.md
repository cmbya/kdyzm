# App 3.1.45 / 后台 3.1.43

后台独立定时采集，App打开先读取已有数据，减少重复请求并让快递信息更新更及时。

- 默认每个平台15分钟一轮：京东在00/15/30/45分起的窗口、拼多多在05/20/35/50分起的窗口、淘宝在10/25/40/55分起的窗口调度，正常每小时各4次。
- 自动采集距离其他平台最近一次开始至少5分钟，重启后不集中补跑。手动刷新、过期补采集及续跑仍可在窗口外执行，保留原5分钟账号冷却。
- App先GET缓存；只有整账号采集严格超过30分钟，或从未采集时才补采集。停用、失效和已有排队/运行任务的账号跳过；多个客户端不会重复排队。
- 单订单刷新、采集进度和手机同步缓存不会刷新整账号完成时间。兼容旧后台；升级后首次完整同步取得新字段，随后继续缓存校验。

首次启动新后台会将已有账号间隔统一迁移为15分钟，保留账号、凭据、授权、历史与启停状态。之后可在账号设置选择30/60分钟，后续重启保留选择。

## 更新

先拉取 ghcr.io/zsdd2/kdyzm:3.1.43 或 latest，保留原数据卷、加密密钥和部署配置重建容器；再覆盖安装同签名App 3.1.45 / 30145，或在“我的 → 检查更新”升级。无需清库、卸载或重新绑定。插件保持1.2.1，无需更新。NAS由用户自行更新。

## 验证边界

按项目完整门禁验证App、服务端、H5构建、Android构建/单元测试/lint及密钥扫描；新回归覆盖模拟一小时调度、重启错峰、迁移幂等、严格30分钟边界、流式请求期间撤权、304缓存与旧版升级。发布包核对原签名、版本和SHA-256，镜像核对amd64/arm64及内置App。

未做真实账号一小时持续运行或实体手机安装验收。15分钟采集会比旧默认60分钟增加后台访问量；平台限流、登录失效和长任务会使实际次数少于理论4次/小时。未运行本地nightly/Semgrep；生产依赖审计与容器验收由发布CI执行。
