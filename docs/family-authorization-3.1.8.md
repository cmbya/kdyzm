# 3.1.8 家人整组授权

后台按已批准 A 方案调整：左侧家人、右侧平台账号；账号详情包含登录与采集配置；设备管理与服务设置为独立入口。App保留原有三个标签和卡片，只增加家人信息、包裹分组切换及绑定识别入口。

## 权限和升级

设备保存稳定的 familyIds，读取时动态计算当前账号。因此空家人组可以授权，以后新增账号自动生效。待归属使用空 familyId，不作为可授权家人组。

旧设备和绑定码迁移时 familyIds 为空，accountIds 保持原有单账号授权；不会自动扩权。管理设备时可以增减家人，原单账号授权可明确勾选清除。两类授权分别有效，移除家人不会自动清除旧单账号权限。

账号首次明确分配家人时回填其既有订单和运单；之后调整归属只改变新订单，历史保留固化家人。拆分运单沿用订单归属。读取快照、操作、定向刷新与任务状态均校验记录权限。在途采集若发生账号移交，其旧结果作废。家人改名只更新显示名，不变更稳定ID。

SQLite升级增加families表和设备／绑定码family_ids列，幂等执行；凭证、账号和订单ID不变。部署升级前备份完整数据卷，保留service-config.json和加密密钥；不要删除数据卷。无需重绑旧设备。新App绑定流程需要3.1.8后台的预检接口，建议先升级后台。

## App绑定与家人显示

应用内相机扫码、相册二维码解码及文字授权码识别共用校验流程。识别内容可修改，服务端预检不消耗授权码，只有确认绑定才兑换；家人名称以服务端返回为准。相机拒绝、识别失败、码过期和网络失败可重试或手动输入。二维码内容不会作为网页直接打开。

远程服务使用HTTPS，本机HTTP仅用于本机联调。相机、二维码和中文OCR模型随Android包提供；网页只在浏览器具备对应能力时识别，能力缺失会提示使用Android或手动输入。

包裹分组仅改变显示，不重复订单、码卡和计数。同服务、同站点、48小时窗口内共享码显示多家人标签，详情逐件领取。短信和手工包裹无法确定归属时保留“待归属”。旧缓存含匿名或待确认成员的码组保守保留，不自动合并。

## 验收

授权、迁移、历史隔离和兼容行为由test/families.test.mjs验证；后台轮询由test/admin-sync-ui.test.mjs验证。App核心、页面及Android单元测试、构建与lint由配套App完整门禁验证。浏览器验收使用内存fixture，不访问真实电商平台；真机相机、相册和实际账号采集需以硬件运行结果为准。

京东和抖音仍未接入，不承诺采集数据。源码上传不代表替用户重新部署服务。
