# App 3.1.39 / 后台 3.1.35

App 3.1.39 / 30139 调整公路小车的阶段进度，并精简取件与订单详情。后台 3.1.35 随本次发布内置新版APK，本轮后台业务接口不变。Chrome插件保持1.2.0。

## 小车按阶段时间推进

小车位置按当前阶段已经过的时间计算，三个阶段分别使用以下基准：

| 当前阶段 | 起点 | 走满当前段的时间基准 |
| --- | --- | --- |
| 待发货 | 可靠的下单时间 | 2天 |
| 运输中 | 可靠的发货时间 | 3天 |
| 待取件 | 可靠的到站时间 | 1天 |

例如，运输阶段已有可靠发货时间，过去1.5天时，小车位于发货至到站路段的50%。超过3天时，该段最多显示100%；只有取得真实到站证据或相应状态，才点亮到站节点并进入待取阶段。待发货、待取阶段遵守同一规则，不因时间经过而自动确认发货、到站或取件。

起点缺失、只有日期、精度未知或时间不可信时，不生成该段的时间比例；不会用首次同步、采集或关联时间补造进度。四个节点继续保留各自真实时间，缺失时保持待获取或未知。

车顶展示包裹实际快递品牌。小车有明显但有限次数的入场和摇动效果，系统开启“减少动画”时停止这些动效。位置反映阶段经过时间，不代表包裹实时地理位置或承诺送达时间。

## 取件与订单详情

- 取件码使用更小、按长度适配的字号，保持单行完整显示；点击复制得到原始完整取件码。
- 展开“订单基本信息”只显示订单号、平台名称、订单状态、快递名称四行。缺失字段显示“未知”，不重复展示平台和状态摘要。
- “更换站点”位于柜号下方；没有柜号时保留独立操作行。更换站点与复制柜号、取件码互不触发。
- 操作按钮的图标和文字居中对齐。商品名称仍默认显示前15字并可展开，原短信、物流详情和基本信息仍可独立折叠。

继续保留 [3.1.38的时间来源与兼容规则](parcel-journey-3.1.38.md) 和 [3.1.37的缓存优先与同步去重](cache-first-3.1.37.md)。独立取件码后续关联包裹时，已知的原取件确认时间仍会保留。

## 升级

本轮发布完成后按以下顺序升级：

1. 拉取 `ghcr.io/zsdd2/kdyzm:3.1.35` 或 `ghcr.io/zsdd2/kdyzm:latest`，保留原数据卷、加密密钥和部署配置，重建容器。只重启旧容器不会更新内置APK。
2. 手机进入“我的 → 检查更新”，或从 [App 3.1.39 Release](https://github.com/zsdd2/kdyzm/releases/tag/app-v3.1.39) 下载原签名APK覆盖安装。不要先卸载App，无需重新绑定。
3. 更新后同步已有账号，查看当前阶段的小车位置和展开后的订单基本信息。没有可靠时间的历史记录不会因升级自动获得时间证据。

无需清库或重建数据库。保留原数据卷与手机应用数据，可继续使用原有订单、短信、领取记录和设备绑定；旧环境变量部署还须保留原加密密钥。本轮不代为部署NAS，正在运行的容器由用户按上述步骤更新。

## 验证边界

本版本的完整验证门禁、APK签名一致性、公开下载大小与摘要校验，以及后台镜像内置APK检查，以实际发布记录为准。文档中的版本号和下载入口不表示这些检查已经完成。

本轮尚未完成OPPO实体手机覆盖安装、真实短信权限及实际运行验收，也未部署NAS。本机自动化与浏览器检查不能代替真机和用户部署后的验收。
