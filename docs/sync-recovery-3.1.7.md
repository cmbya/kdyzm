# 3.1.7 订单发现与采集状态修复

本版补齐拼多多待发货采集与跨端刷新状态。源码推送主分支后，GitHub Actions通过测试与容器验收才更新镜像；飞牛需另行拉取并重建容器。无需清库、改密钥或重新绑定。

## 拼多多待发货

此前只查询 `type=unreceived`。从2026-10-31的[官方订单页](https://mobile.yangkeduo.com/orders.html)及其[官方脚本](https://static.pddpic.com/assets/js/react_orders_7c4eb98c8a268eacd674.js)核实：待发货为UI type 2，对应 `unshipping`；待收货为type 3，对应 `unreceived`，offset按type分别保存。现在同时读取这两个范围，各自最多5页，按order_sn去重，状态过渡继续更新同一订单。

无运单的待发货订单只保存订单，不查取件柜和物流。明确取消、交易结束、未付款或全额退款完成的新单不导入；原有历史保留。未知数值状态不猜测为结束，物流签收、驿站代收或退款处理中也不等价于本人取件。任一列表查询失败会使任务报错，保留上次成功快照，避免把部分返回当成全量成功。

官方脚本当前用POST；本轮保持项目已运行的GET传输，仅扩展已核实的type。新增范围的真实账号返回仍需部署后验证，模拟通过不代表已补回用户真实订单。

## 冷却与状态

每账号两次采集开始时间至少相隔5分钟。冷却期间提交的同范围请求合并为一个queued任务，携带retryAt，到期执行一次；不会因重复点击延长冷却，也不会无限重试失败。队列最多25个等待范围，满时仍返回cooldown并明确“未排队”。停止服务会终止等待任务；重启不恢复内存中的手动请求，用户需重新提交。

job兼容已有state，补充createdAt、finishedAt。管理账号查询额外返回最近全账号syncJob和serverTime，无Cookie。网页用服务端时间校准倒计时，pending每3秒、空闲每30秒只读查询账号状态，隐藏/退出时停止；手动刷新清除旧提示。表单草稿、绑定选择保留。完成任务仍显示部分日期/物流失败。

App继续GET轮询queued/running，前台25秒软等待后提示仍在后台排队或采集。旧服务返回的cooldown到期后显示“本次采集未执行，现可重新获取”，不会自动重复POST，也不会伪造completed。仅同账号成功时间达到旧retryAt且账号无错误时清理旧冷却；其他账号的真实失败仍保留。

## 验证与边界

回归覆盖两范围独立分页、去重、发货状态过渡、无运单订单、驿站代收、列表失败保留历史、冷却自动执行一次、重复请求、停用/停止、跨端状态恢复、时钟偏差及网页轮询竞态。全量项目门禁包含前端/服务端单元测试、源码密钥扫描、H5构建、Android打包/单元测试/lint；另用本机内存服务做浏览器验证。

本地验证未触发用户真实账号采集，不改变电商平台订单，不操作飞牛生产数据。镜像构建和amd64容器验收由发布工作流执行，结果以对应GitHub Actions记录为准；arm64实际运行、真实手机安装及真实平台补单仍需部署后验收。
