# 3.1.32 App / 3.1.28 后台

## 业务规则

- 取件码可以独立标记已取、部分已取或撤销，不要求匹配订单。关联证据有歧义时只记录该取件码的领取，不替候选包裹生成领取命令；用户明确关联后再继承确定的领取状态。
- 所有订单超过30个中国日历天进入过期订单，时间依据依次为人工日期、可信平台下单日期、首次记录时间。第30天仍在当前订单，第31天归档；未完成不再豁免。
- 过期且物流已签收，显示“超期自动确认收到”；运输中、未签收、退回中的订单只归档。此状态是本系统的收货投影，原始物流及本人领取事实继续保留，不向购物平台确认收货。
- 过期订单可以查看、恢复。恢复记录保存日期依据和时间，在相同日期依据下不会立即再次归档；新的日期依据仍按新日期计算。
- 隐藏与过期是独立状态。恢复过期不擅自取消用户隐藏决定。

## 身份修复

旧版可能因承运商别名、运单全角字符生成重复包裹。只在同账号、同订单、已知规范承运商和规范运单一致，且分包键、物流周期、人工决定及站点/取件码证据不冲突时，保存持久身份别名。原行保留，手机按明确周期桥收敛已有副本，保留绑定和离线操作；不同真实分包不按标题或数量合并。

## 可见记录

后台优先显示已保存的脱敏原站名。确实缺少原站名的修正显示“未提交（无可学习的原站名）”，保留人工确认记录，不把物流站名充当短信原文，不虚构历史短信。

手机“查看自动取件记录”在本页展开领取历史，点击具体“查看包裹”才打开详情。人工修正提交、后台处理与规则回执仍在人工修正优化区查看；规则已应用不等于模型效果已经验证。

## 验证边界

发布前验证使用合成订单、短信、临时SQLite库、H5浏览器与Android自动化测试。没有读取或修改用户真实订单，也没有调用真实AI模型；真实设备及已有NAS实例需更新后验证。
