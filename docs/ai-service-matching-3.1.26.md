# App 3.1.26 / 后台 3.1.23：统一AI服务与逗号物流匹配修复

手机旧版本只允许两种AI能力，后台3.1.22增加物流能力后，手机拒绝整个响应，导致已经配置的服务显示为空。3.1.26接受三项能力，所有手机AI统一使用后台选择的默认服务，取消手机渠道选择与本机密钥入口。后台更换默认服务后，手机刷新或下一次分析会跟随；暂停、缺配置与网络错误分别说明，不偷偷使用其他服务。原来的自动建议授权保留，未开启的手机不会自动开启。

截图订单并未被判为送上门。完整物流文字中，“已送达…暂存”与“取件地址”被逗号分隔，旧解析器丢失具体站点和到站时间，因而没有自动匹配证据。新版只连接相邻且已完成的暂存动作与明确取件地址；仍保留未来、否定、上门和途中物流保护。按截图结构、完整标点、电话尾及已确认站点别名回放，同站50秒唯一候选可自动关联；手机旧缓存也会重新解析。

手动匹配原来默认只展示推荐候选，容易误以为订单不存在。新版无推荐时直接显示可关联的未完成包裹，商品、订单号和运单号搜索覆盖这些包裹。权限限制、冲突确认、件数上限及已取保护继续保留。

## 更新

1. 保留原数据卷和密钥，拉取3.1.23或更新的后台镜像并重建原容器。
2. 覆盖安装App3.1.26，不卸载，不必重新绑定。
3. 后台仍在“服务设置 → 站点目录 → AI设置”管理服务，选择有效默认服务即可。手机“AI识别优化”只显示该服务，点击“刷新服务状态”可立即核对。
4. 手机保留的原物流会自动重算。后台历史记录在下次正常采集导入时刷新解析；重启本身不会全库迁移。已归档、已取、人工解除或冲突包裹继续遵守原保护。

## 验证范围

回归覆盖三能力响应、默认服务切换/在途失效、旧授权保留、没有默认服务不回退、完整逗号原文和旧缓存重算、手动候选与权限边界。运行页面使用合成数据，模拟器与发布门禁证据保存在本地任务记录。合成验证不代表真实AI模型准确率或实体手机已验证。本次发布不代替NAS部署，不修改生产AI设置。
