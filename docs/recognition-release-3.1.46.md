# App 3.1.46 / 后台 3.1.44

未收包裹显示实际商品图片，缺时间和匹配失败会持续追踪，三次真实重采后才交给AI辅助。

- 首次只接纳当前未收、待发货和后续新增包裹，不回填历史订单图片或详情。正在追踪的包裹保留最终完成更新，避免一直停在待取；驿站代签不等于实际领取，拆单逐包裹处理。
- 淘宝、拼多多、京东分别读取结构化订单、物流与商品图片。图片缺失或加载失败保留示意图；旧记录不批量补图。
- 异常持久保存，首次失败后按5、10、15分钟间隔重采。只有实际完成的采集作业计入三次，排队、冷却、登录过期和账号停用不计数；同订单问题合并请求。
- AI回复使用固定JSON与逐字原文证据，候选只能来自本次授权输入，不猜时间、不因只有一个候选就强配。确定性解析通过或客户端明确确认完整匹配才标记解决；规则保存和下载均不代表实际效果。
- 后台每天北京时间03:00巡检未收包裹，即使AI关闭也发现问题和统计。AI调用、自动应用及预算仍遵循现有配置；忽略、删除、撤回和授权变化会停止对应处理。
- 保留每平台15分钟、三个平台错开约5分钟的调度，App先读缓存，整账号超过30分钟才自动补采集；手动刷新仍可主动获取。

## API联调与持续复盘

能力标记为recognition_workflow_v1。App通过POST /v1/recognition-issues提交版本化异常、解决确认和撤回；旧后台没有该能力时不上传，原包裹同步保持兼容。管理员接口GET /v1/admin/recognition-tasks展示任务与日报，GET /v1/admin/recognition-review?limit=100&after=0提供未收样本、规则版本和AI建议，按nextCursor分页。认证、字段限制和固定回复协议见[PROTOCOL.md](../PROTOCOL.md)。

外部复盘工具可通过已有管理员认证调用只读API；发布包不包含管理员凭据或本机自动化任务。会话过期必须重新认证。没有真实确认的样本只记录未验证，不据此宣称准确率提升。

## 手动升级

先拉取ghcr.io/zsdd2/kdyzm:3.1.44或latest，保留原数据卷、加密密钥和部署配置重建容器；再覆盖安装同签名App 3.1.46 / 30146，或使用“我的 → 检查更新”。无需清库、卸载或重新绑定，插件保持1.2.1。更新由使用者操作。

升级后可用已登录管理员会话读取上述API，确认能力和任务出现；每天03:00后核对巡检日报。AI未启用、预算不足或autoApply关闭时会保留相应等待/待核对状态，不会擅自改变设置。
