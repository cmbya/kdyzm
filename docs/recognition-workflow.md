# 未收包裹识别闭环

App 3.1.46 / 后台 3.1.44。复用原有三平台采集器、同步任务、站点规则、物流规则、AI渠道和回滚记录。

## 采集范围

- 首次采集只接纳当前未收订单、待发货订单及后续新增包裹；不回填历史订单的图片或物流详情。
- 已追踪的未收包裹保留最后一次完成更新，以免“停止采集已完成订单”导致 App 永久停在待取。
- 用户已取、隐藏、删除或归档的包裹退出重试和学习；平台驿站代收不等于用户已取。拆单仍逐包裹判断。
- 淘宝现有列表接口可能返回历史条目，但历史条目不会进入图片、详情与后续学习流程；不通过遍历历史补图。
- 既有历史数据保留，不清库、不改用户手动取件决定。

## 处理顺序

1. 按淘宝、拼多多、京东分别解析结构化订单、物流事件和商品图。
2. 发现物流详情不可用、事件时间冲突/缺失、到站时间证据不足，或客户端未匹配取件信息时，建立持久问题任务。
3. 首次失败后，分别等待 5、10、15 分钟重采对应订单。同一订单的多个问题共享请求；只有真实完成的采集任务计数。排队、冷却、账号停用、登录过期不消耗次数。
4. 三次后进入 AI；复用已配置渠道、开关和每日预算。未配置或预算不足保留任务，等待恢复。
5. 物流规则复用已有原文提取、反例验证、应用与回滚。时间和匹配不确定项只生成带原文证据的核对建议，不猜年份/时间，不因候选只有一个而强制匹配。
6. 服务端确定性重新识别通过，或原设备新版本报告明确确认完整匹配成功，才记为 resolved。AI 返回、规则保存、客户端下载规则均不等于解决。

任务按 `platform + contentKind + target + methodId + methodVersion` 分组。目标为 `logistics_detail`、`event_time`、`arrival_time`、`station_match`；同一故障不重复创建 AI 请求。任务、重试作业身份和每日游标均持久保存。授权撤销、家人归属改变、证据改变及服务停止都会阻止迟到结果继续生效。

## AI 回复协议

时间/匹配辅助只接受以下固定字段，拒绝附加字段和没有输入证据的内容：

```json
{
  "version": 1,
  "target": "station_match",
  "action": "review_match",
  "reasonCode": "STATION_NAME_VARIANT",
  "candidateId": "candidate-1",
  "evidence": [
    { "sourceId": "source-station", "quote": "原始站名" },
    { "sourceId": "candidate-1-station", "quote": "候选站名" }
  ],
  "requiresReview": true
}
```

`candidateId` 仅引用本次输入候选；两侧站名证据都必须逐字来自原文。卡号/柜号冲突不允许推荐。时间类只建议核对格式，不返回新时间戳。物流规则继续使用已有 `kind,starts,ends,keywords,expectedStation,evidence` 协议并经过原文和规则测试。

## 两条每日链路

后台每天北京时间 03:00 巡检本地真实未收包裹，AI 关闭时也执行问题发现、确定性复核和统计；关闭服务后恢复会续扫。每批 100 条、每日最多 10000 条，游标支持重启恢复；保留 90 天日报和最多 500 条已结束任务。AI 学习层另受现有 AI 配置约束。保留 `autoApply` 开关，不因开启巡检擅自开启自动应用。

外部复盘工具可使用已有管理员认证调用下列只读接口。会话过期需重新认证；凭据和本机自动化计划不包含在发布包中。

复盘只读以下接口：

- `GET /v1/admin/recognition-review?limit=100&after=0`：当前有效样本、任务分组、每日巡检、规则版本、AI 建议和预算；按 `nextCursor` 分页。
- `GET /v1/admin/recognition-tasks`：任务策略、最近任务和日报。
- 既有 `logistics-ai`、`matching-feedback`、`ai-optimization/history` 接口：核对建议、客户端回执及规则回滚。

复盘应记录最小失败样本与回归用例，先本地验证后再发布；不要将私人订单或凭据写入公开仓库。

## 效果与兼容

分别记录首次失败数、真实重试次数、AI 调用、待核对、确定性解决和客户端确认。没有人工/客户端真值时不生成“准确率”。已应用规则仍需后续样本和客户端结果证明有效。

新客户端仅在快照包含 `recognition_workflow_v1` 时上传；旧后台继续同步原有包裹。报告包含最多 20 个授权候选、版本和最小来源字段，关闭站点片段增强时不上传站名/片段。H5 与 Android 串行提交精确回执；后台状态刷新不额外触发平台采集。既有三平台错峰 15 分钟调度、前台 30 分钟过期策略和手动刷新保持有效。

实体手机和线上新机制长期效果仍需升级后验收。
