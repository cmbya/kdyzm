# 包裹身份、站点重识别与取件列表优化

App 3.1.33 / 后台 3.1.29，插件仍为 1.2.0。

## 包裹身份与历史保护

同一账号、订单、运单，承运商从“快递”等泛称变为具体公司不再创建新包裹；已有泛称重复记录在唯一兼容时通过身份别名收敛，保留绑定、历史和离线操作。明确不同的平台分包标识仍独立，缺少标识且候选不唯一时不猜测。拼多多列表、详情、柜记录和单订单更新统一运单格式，并过滤待发货等占位值。该修复覆盖截图对应的重复机制；未读取生产数据库核对实际 N35 记录。

“时间未知”若来自未到站包裹，继续显示未知；不补造到站时间，不重新匹配旧版已经完成的历史订单。普通物流变化继续保留已建立绑定；本人领取、退回、上门及改投沿用现有周期规则。

## 站点优化后的刷新

后台应用人工或 AI 站点规则后，从原始物流证据重识别启用账号中未取、未自动完成、未归档且未唯一归属目录站点的包裹；常规同步和冷却期更新也会触发。手机一键更新等待短信与线上更新结束后，再刷新未分类站点并匹配。

只有明确完成的入库、暂存或送达取件点等证据可提供站点与到站时间，预期、失败、催取、退回、本人已签收等不能冒充到站。物流“已签收”若实际是驿站代收且用户未领取，仍可使用可信到站证据。人工覆盖、现有明确站点、已取历史及歧义保护保留。AI 仍是有审计和回滚的规则优化，不是模型在线训练。

## UI 设计与实现方案

沿用 uni-app/Vue、项目字体及原交互。用户确认 C 方案：左侧柜号、中间取件码、右侧放大取件按钮，菜单在右上；按苹果风格细化字号层级、字距、行高及对齐，取件码与柜号使用蓝色突出；码、商品、时间区域预留统一高度，短内容和缺柜号也保持列对齐。商品名最多显示10个字，超出加省略号，完整名称保留在详情；平台来自已关联商品，不从短信承运商推测。未关联、未知柜号、长码、长商品名及已取状态均纳入手机与桌面宽度验收。沿批准的卡片方向局部调整，不增加独立页面或依赖。

展开历史仍先显示未取；同站内按柜号自然排序，同柜集中排列。通知逐条关闭只影响当前设备显示，不确认领取、不修改订单；关闭记录隔离绑定账号，事项有新内容或进展时重新提醒。关闭控件保持触控范围、键盘焦点与明确朗读标签。
