# App 3.1.38 / 后台 3.1.34

App 3.1.38 / 30138 按已批准的公路卡片与详情稿，集中展示每个包裹的下单、发货、到站和取件时间。后台 3.1.34 保存时间证据及精度，兼容已有订单和包裹数据，无需重建数据库。

## 界面与使用

- 待取卡片用公路四节点展示包裹进度；已取卡片展示四个时间，便于回看过程。
- 商品名称默认显示前15字，可展开查看完整货名。
- 订单详情中的原短信、物流轨迹和基础信息默认折叠，需要时分别展开。
- 缺失的时间显示未知，不以同步时间补齐四个节点。只有时间来源、精度和先后顺序可靠时才展示相应耗时。

保留原取件码、柜号、角色、独立领取和匹配操作。3.1.37的缓存优先继续生效：先显示本地已有数据，再异步连接后台；快照复用、轻量统计和账号读取、重复同步合并继续保留。

## 时间来源与兼容

下单时间继续取平台真实订单时间，保留来源与原始精度。人工修正的日期与平台时间分开，只有日期的记录不会被当作精确到分钟的下单时间。

发货时间只取当前配送周期内明确已发货或已揽收的物流事件。运单生成、仓库打印、运输中状态和本次查询时间都不构成发货时间。到站使用可信物流到站事件或平台明确的实际入柜时间；短信接收时间和柜机记录创建时间不冒充实际到站。

取件时间区分平台明确领取／本人签收事件与用户在App内确认的时间。自动识别使用物流事件时间，不使用后台检测时间；人工确认保留原确认时刻。独立取件码先领取、后关联线上包裹时，已知的原取件时间继续保留；旧记录没有可靠时间时仍为未知，不改成本次关联时间。恢复未取和恢复自动识别也不会生成新的取件时间。

一单多运单分别保存证据。退回、改派或重新配送会划分周期，当前周期不套用旧周期的发货或取件时间。无时间的重派记录、未来时间、缺失精度及无法确认顺序的记录，不用于生成准确耗时。

物流轨迹仍最多保存100个节点，其中保留当前周期的关键发货、到站和配送边界证据；已保存的时间字段供后续快照直接读取。大快照裁剪本次返回内容时保留数据库缓存。历史上已经丢失的节点、平台未返回的字段无法凭升级恢复，仍需后续获得真实证据。

## 升级

本轮发布完成后按以下顺序升级：

1. 拉取 `ghcr.io/zsdd2/kdyzm:3.1.34` 或 `ghcr.io/zsdd2/kdyzm:latest`，保留原数据卷、加密密钥和部署配置，重建容器。
2. 手机进入“我的 → 检查更新”，或从 [App 3.1.38 Release](https://github.com/zsdd2/kdyzm/releases/tag/app-v3.1.38) 下载原签名APK覆盖安装。不要先卸载App，无需重新绑定。
3. 更新后同步已有账号，查看四个节点；尚未取得可靠时间的历史记录继续显示未知。

现有SQLite数据库及JSON记录兼容读取，无需清库或重建数据库。保留短信、包裹、领取记录与设备绑定，Chrome插件保持1.2.0。本轮发布不代为部署NAS，正在运行的容器由用户按上述步骤更新。
