# App 3.1.47 / 后台 3.1.46

修正京东仓库准备阶段的发货判定，并让每次冷启动App后首次滑入可见范围的包裹播放小车行程。App与后台需配套升级，Chrome插件保持1.2.1。

## 京东以实际揽收为准

- 进入仓库、打印、打包、准备出库、等待揽收、商家已发货及生成运单，不再单独作为京东实际发货证据。明确揽收才提供发货时间，App列表与Android桌面组件使用同一判定。
- 已有真实后续运输节点时仍显示运输中；缺少揽收时间就保留未知，不用仓库时间补齐。到站、签收、人工领取和退回流程保留，淘宝、拼多多规则不变。
- 每个运单只使用自身轨迹，不借用同订单其他包裹的运输或签收证据。本次返回的取件码不会被较早揽收记录覆盖；订单显示已发货、当前运单仍待揽收时，包裹继续保留在默认未收到列表。
- 后台重新计算旧京东发货时间缓存，并向新版App传递未知时间以清除旧错误。平台尚未返回揽收节点时仍显示未知；升级后正常采集和App同步才能取得后续物流结果。

## 每次启动，各包裹首次可见播放一次

每次冷启动App后，未完成包裹的小车区域首次完整可见时，从下单站播放至真实位置。首次进入页面已可见和向下滚动后可见都适用；滚动回来、切换页面或重新打开详情不会重复播放。冷启动开启新一轮播放机会，真实物流阶段推进仍保留原动画。

可见范围扣除固定底部导航的遮挡，以小车、投影和承运商标识区域为准；短横屏不要求整张地图同时可见。包裹离屏或App退到后台时，不提前消耗首播机会。待发货、历史完成、摘要和减少动态效果时保持真实静态位置，不制造发车；已完成包裹继续显示收拢后的时间记录。

## 手动升级

1. 在NAS保留原数据卷、加密密钥和配置，拉取 `ghcr.io/zsdd2/kdyzm:3.1.46` 或 `ghcr.io/zsdd2/kdyzm:latest` 并重建容器。普通重启不会下载新镜像。
2. 从[App 3.1.47 Release](https://github.com/zsdd2/kdyzm/releases/tag/app-v3.1.47)下载同签名APK覆盖安装，或在「我的 → 检查更新」升级至3.1.47 / 30147。不要先卸载旧App。
3. 正常同步后核对京东包裹状态，再关闭并重新启动App，向下滚动查看各包裹首次可见播放。插件1.2.1无需更新，无需清库或重新绑定。

NAS更新由使用者自行执行；发布源码、安装包和镜像不会自动更新正在运行的容器。
