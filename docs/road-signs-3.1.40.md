# App 3.1.40 / 后台 3.1.36

App **3.1.40 / 30140** 将取件卡片、包裹记录和订单详情统一为已确认的路牌时间轴。后台 **3.1.36** 配套内置新版APK，业务接口和数据库不变；Chrome插件保持 **1.2.0**。

## 路牌、时间与小车

- 下单、发货、到站、取件四块烤漆单柱路牌立在道路上方，只有真实到达或已经过的节点点亮；未来节点保持灰色，不因时间经过自动确认。
- 每块路牌使用独立的日期时间牌，未知时间显示“—”。缺失、日精度、短信代理时间或时间逆序等不足以计算的情况不制造准确耗时，也不使用同步、采集或关联时间补造历史。
- 小车车轮落在上车道，实际快递品牌显示在车顶。当前阶段继续按待发货2天、运输3天、待取1天计算比例，超期最多走满当前段；下一节点仍需真实证据。位置表示阶段经过时间，不代表实时地理位置或承诺送达时间。
- 发货、运输、取件三段耗时位于道路下车道，名称沿道路曲线排列。已结束阶段显示对应真实时间差，进行中显示“已用”，所有道路卡片共用一分钟时钟更新。
- “更换站点”与站点名称同行居中，长站名可以换行。原取件码单行完整显示与复制、货名展开、短信和物流折叠继续保留；有限动效遵循系统减少动画设置。

独立取件码没有订单时仍可显示实际进度，缺失的历史日期保持未知；后续关联包裹仍保留已有的原取件确认时间。已完成记录继续使用紧凑摘要。设计对照与实现截图见 [路牌时间轴](designs/road-signs-20261109/README.md)。

## 升级

1. 拉取 `ghcr.io/zsdd2/kdyzm:3.1.36` 或 `ghcr.io/zsdd2/kdyzm:latest`，保留原数据卷、加密密钥和部署配置，重建容器。只重启旧容器不会更新内置APK。
2. 手机进入“我的 → 检查更新”，或从 [App 3.1.40 Release](https://github.com/zsdd2/kdyzm/releases/tag/app-v3.1.40) 下载原签名APK覆盖安装。保留原应用数据，不要先卸载App。
3. 更新后同步已有账号，在取件卡片或订单详情查看路牌、时间和更换站点操作。没有可靠时间的历史记录不会因升级自动获得时间证据。

无需清库、迁移数据库或重新绑定。旧环境变量部署继续保留原加密密钥；旧设备协议、原有订单、短信、领取记录及绑定继续兼容。本轮不代为部署NAS，正在运行的容器由用户按上述步骤更新。

继续保留 [3.1.39阶段进度](journey-progress-3.1.39.md)、[3.1.38时间来源与兼容规则](parcel-journey-3.1.38.md) 和 [3.1.37缓存优先与同步去重](cache-first-3.1.37.md)。
