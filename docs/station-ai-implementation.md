# 站点别名与 AI 增强：App 3.1.16 / 后台 3.1.13

本次实现沿用已批准的方案 B：站点目录与详情，以及 AI 整理、人工核对后加入规则的流程。[Figma 归档](https://www.figma.com/design/o3UafBmvkhXfUEXVXmGZYC?node-id=1-2)对应本机 `station-alias-20261103` 批准源稿。下文描述当前实现，测试与发布状态见末节。

## 站点管理与人工核对

后台入口为「服务设置 → 站点管理」。左侧选择站点，右侧维护标准名称、所在地区、完整别名、来源与子位置（例如2号柜），也可暂停站点。一个规范化后的名称不能同时属于两个启用站点；暂停规则只停止参与新匹配，保留既有关联。

「匹配验证」使用已保存规则检查两端是否同站、是否存在位置冲突。它不能证明两条信息属于同一包裹；自动关联仍检查到站时间、候选唯一性及其他冲突。

左侧「AI 待核对」收集待分析片段与建议。管理员核对原片段、别名、目标站点和柜号后，可选已有站点或填写名称、地区新建站点，再点击「确认加入」；也可忽略。AI 返回、分析完成和设备提交都不会直接启用规则。确认的别名、柜号须引用片段，AI 不能编造证据；中转、分拣、发货仓及住宅等材料在本地校验层拒绝。

App 的「匹配订单」可选「记住这两个名称属于同一站点」，默认不勾选。它只提交两种原站名供后台分别核对，不会替管理员批准规则，也不会给未提供柜号的一端补写柜号。明确位置冲突时不提供这一选项，本次人工关联仍按原确认流程处理。

## 后台 AI 渠道设置

进入「服务设置 → 站点管理 → AI 待核对 → AI 设置」，填写渠道名称、兼容 Chat Completions 的公网 HTTPS Base URL、模型与 API Key，保存后可点击「连接测试」。Base URL 填接口根路径，例如 `https://api.example.com/v1`；后台在其后追加 `/chat/completions`。保存配置本身不请求模型，连接测试发送固定测试内容，不带站点片段。

后台密钥独立于手机上的短信模板辅助配置，不会从手机复制。API Key 在后台加密保存，读取设置只返回是否已配置及掩码；输入框留空保留原密钥。「清除 Key」同时暂停定期分析。请求只允许公网 HTTPS，校验 DNS 解析结果并固定已校验地址，拒绝私网、特殊地址与重定向。

定期 AI 初始关闭。配置完整并启用后，默认每小时整理新增去重材料，可改为每天；也可点击「立即分析」提交后台任务。频率表示后台处理已收到队列的间隔，不承诺整点完成手机扫描或上传。没有可处理材料时不调用模型。

每日调用上限默认20次，可设为1到20次，连接测试和失败重试也计入；按北京时间日期计数。临时失败有限重试，单条最多尝试3次；超时、限额或渠道失败不会阻塞订单采集与 App 同步。重复材料按片段去重，已处理或已忽略且没有新材料的项目不反复分析。AI 只产生结构化建议，最终仍须人工确认。

## 手机开关、隐私与上传

App 入口为「我的 → 定时识别与桌面卡片 → 站点片段增强 → 提交未识别站名」。初始默认关闭，绑定支持站点管理的后台并同步后才可开启；开启前弹窗说明片段会提交给当前后台及其配置的 AI 服务。开启手机上传与启用后台 AI 是两个独立操作。未开启手机上传时，后台仍可整理其已有物流站点材料。

手机只从疑似取件短信中提取可用的公共站名短片段，过滤姓名称谓、电话、链接、订单号、运单号和取件码等无关内容；保留“4卡”“2号柜”“3栋”等位置数字。无法提取合格片段时不上传完整短信，转由人工处理。后台不直接读取手机短信，普通营销、金融及验证码短信不进入候选。

手机本地队列最多200条、保留7天，每批最多20条。候选上传独立于订单同步，失败保留到后续同步重试，收到后台对本批项目的成功确认才移除。关闭开关会清空待上传队列；换绑或解绑会清理队列与规则，旧会话迟到的响应不能确认新会话。已删除、已忽略或已取的短信来源不继续上传。设备快照只下发已启用规则，不下发后台待核对片段或 AI 密钥。

## 规则同步与 App 变化

后台 3.1.13 声明 `station_aliases_v1` 能力；规则版本随快照和 ETag 更新，设备同步后重算仍有效、未关联的待取记录。未声明该能力的旧后台可继续原有订单同步，手机不提交站点片段或站名关系。

“四卡／4卡”只在明确位置单位前归一；专名数字、品牌与站型不随意删改。柜号、卡位、楼栋、门向、承运商及运单冲突继续保护，重叠规则有歧义时转人工核对。新增别名不首次关联已取、归档、隐藏或失去授权的记录，也不替换人工关联、恢复人工解除；原有精确同名同码及同运单的后补信息契约保留。

平台无码时的时间匹配仍要求真实到站时间相差不超过60秒，分钟精度沿用同分钟限制，且短信和运单双方唯一。站点统一不会将同站所有包裹合成一件；多候选继续由用户选择。

App 保留现有页面与桌面卡片布局。包裹分组用词改为「时间 / 角色」，并明确「一键更新」「短信定时识别」「扫描授权码」「暂无取件码」「站点未知」「更新订单」「隐藏订单」等操作。后台授权继续使用「家人」，不引入新的角色权限模型。
