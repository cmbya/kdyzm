## 匹配策略

截图中的短信13:14:38与物流13:13:48实际相差50秒；原先物流品牌、动作和重复括号站名混入地址，也会阻止匹配。本版修正明确取件地址的提取，同时保留柜号、卡位、楼栋和门向等差异。截图两种站名是否确为同站，仍需后台确认别名关系。

| 证据 | 新行为 |
| --- | --- |
| 运单号或已有取件码与站点等精确证据 | 保留原有匹配路径 |
| 已确认同站、真实到站时间差≤5分钟、双方无竞争候选 | 自动关联 |
| 已确认同站、5–30分钟，另有真实承运商或明确柜号/已确认子位置一致 | 自动关联，仍需双方唯一 |
| 只有时间接近、站名尚未确认、存在多个候选或多件短信 | 推荐核对，不选择最近一件强行合并 |
| 同站但时间更远 | 48小时内推荐；未知到站时间明确显示未知 |

分钟精度按时间区间计算。同步时间不能冒充到站时间；兔喜、菜鸟品牌不作为独立承运商证据。保留人工解除、人工关联、授权范围、已取/归档和后补冲突核对。

## AI 使用流程

1. 后台「服务设置 → 站点管理 → AI待核对 → AI设置」保存统一渠道：名称、HTTPS地址、模型、API Key。最多10个，密钥加密保存在后台。
2. 点击「连接与能力测试」，分别检查站点别名和短信模板的合成样例。通过只代表这些合成检查成功，不代表真实短信准确率。
3. 后台可选择渠道并开启站点自动优化；手机仍需主动开启原有「站点片段增强」。建议别名在后台核对批准后才生效。
4. App「我的 → 短信识别规则」选择同一渠道目录中的渠道，主动开启自动准备。未识别且符合安全条件的取件短信会自动分析，用户只需核对样例、提取位置并「确认使用」或「忽略」。确认使用同时保存规则并识别该原短信，不再要求手动重复扫描。

只发送由已知品牌、取件码标记和虚构码组成的最小合成片段。真实短信、取件码、姓名、电话、地址、单号不发送。验证码、金融/营销、多码歧义及无法安全构造的材料留待手动处理。建议最多20条、保留7天；默认关闭，关闭/手机切换渠道/更换绑定会清除未确认建议。已保存规则继续本地运行。

后台共享每日额度包含所有渠道、站点任务、短信模板和测试；失败不显示成功，超时、停用、权限变化与迟到响应受到约束。后台渠道编辑取消在途请求；已经完成本地校验的候选可以继续由人确认。旧后台单渠道自动兼容为默认渠道；手机旧DeepSeek密钥留在本机，仅供手动明确选择，不会上传迁移或自动回退。
