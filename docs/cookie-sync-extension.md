# Chrome 登录同步配套开发

此功能为淘宝、拼多多、京东提供角色范围的浏览器登录同步，兼容原有单账号通道。源码与安装说明位于 `cookie-extension/README.md`，接口契约位于 `PROTOCOL.md`。现有后台及 App 设备授权不替代插件授权。

TASK-039增加角色一码、插件按平台选择，以及插件先登录再向后台发起授权。后台只需有角色，用户在后台明确选择角色批准，插件取得仅限此角色的授权；首次批量核对后才创建缺失的平台账号并保存加密Cookie。请求和核对阶段只持久化摘要，不提前创建账号或保存Cookie。后续新增账号默认关闭；角色转移令原有子授权失效，移回也必须重新核对。用户的反向授权补充要求并入TASK-039，由同一任务承接验证与既有仓库发布范围。

## UI 设计与实现方案

沿用已批准后台工作台的蓝色按钮、白色表单、圆角、字体和间距。后台仅在已有账号详情抽屉加入配对与撤权区域；插件将这些既有表单样式复用为窄幅设置页，未引入新的视觉方向、图表、组件库或框架。原生 HTML/CSS 与 ES 模块，适配桌面和 390px 宽度。覆盖初始读取、空配对、权限拒绝、配对预览、首次确认、等待采集、账号不匹配、网络失败、过期、撤权及同步中状态，全部调用实际新增接口。

TASK-037完成基础版本，TASK-039继续复用这些原生表单、复选框、dialog和蓝白样式。角色操作区添加插件授权按钮，插件增加角色卡片、三平台选择和反向授权等待区，后台以既有弹窗选择角色；没有改变批准的视觉方向，不新增Figma流程。状态包括未登录、权限拒绝、空角色、等待批准、过期、首次批量核对、部分成功、平台取消选择、撤销与重开恢复，覆盖桌面和390px宽度。

后台模块/测试、后台UI、插件UI由隔离文件责任的子任务处理，主代理负责插件worker、集成、共享状态、安装包与最终验收。使用同一独立审查者检查授权，完整门禁验证兼容性；实际Chromium隔离配置通过合成HttpOnly Cookie测试角色反向批准、批量创建、拼多多自动更新、取消选择及转组保护。扩展服务worker和加载路径需要持久浏览器上下文，沿用TASK-037的Playwright扩展验收fallback；测试副本仅预授予测试域，正式manifest仍按用户手势申请可选站点权限，原生权限弹窗不由自动化批准。

## 维护

TASK-040：插件1.1.2与后台3.1.20增加JD `thor OR light_key`结构校验，仍使用同一`pin/pt_pin`身份绑定与PC采集接口；裸pin、flash、pt_key不作为登录凭据。URL Cookie查询缺必需字段时，补查已授权平台域并严格保留原请求域/path边界，不选取冲突值。单账号、角色账号及反向请求共用同一读取函数。缺字段诊断仅输出字段存在性/已知范围/过滤原因。合成测试可复现URL遗漏PDD身份字段，但真实插件补查结果仍需用户更新后确认；没有把此模拟场景当作已证明的Chrome缺陷。

- 插件是 Manifest V3，无额外运行依赖。按源码目录加载，文件清单固定。
- 插件不把浏览器登录等同于平台认证成功；后端采集状态负责反馈真实可用性。
- 后台持久化独立配对/角色授权/反向请求/首次确认摘要表及账号转组撤权触发器。新增平台账号、子授权及确认消费在同一事务提交；失败完整回滚，不更改已存订单。
- 后台版本发布、Chrome 商店上架和实际 NAS 部署分别处理，开发测试不操作生产数据。
- CodeGraph 在本项目及发行仓库没有索引；本次通过源代码、实际调用方、回归测试和唯一独立审查确认范围，未自行初始化索引。
