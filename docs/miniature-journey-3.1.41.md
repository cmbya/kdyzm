# App 3.1.41 / 后台 3.1.37

取件列表、包裹记录、取件详情和订单详情统一使用微缩站台物流进度。沿用原有浅蓝灰磨砂卡片，采用象牙色弧顶站台、淡地图、浅弯公路及蓝色小车与纸箱拖车。设计来自用户确认的完整效果图与透明素材包，见 [Figma 定稿](https://www.figma.com/design/8vZ33CfpH5T718wSficdf0?node-id=113-2)。

## 状态与时间

- 打开直接定位当前真实阶段，不回放历史。下单停第一站；发货后停在发货和到货之间；到货后停靠到货站；用户确认或可靠取件回执才到终点。旧版按 2/3/1 天推进车位的规则由本版替换。
- 新事件播放约 1 秒行程，车轮转动、拖车跟随、纸箱短暂晃动；细蓝进度线跟随车尾。下单站蓝色，实际经过的其他站台绿色，未来站台灰色且时间为“—”。
- 发货时间＝发货−下单，运输时间＝到货−发货，取件时间＝取件−到货。三段真实耗时喷印在对应路面，保留分钟；进行中由共享一分钟时钟更新。无可靠精度、缺失或逆序不伪造用时。
- 新确认取件后四站停留约 0.8 秒，再平滑收拢为 2×2 时间记录和三段耗时。列表暂留完成卡片以播放结束；重复同步不会重播。历史完成订单直接展示摘要。
- 商品、取件码、短信和其他详情的既有折叠继续保留，减少动画设置下直接定位。

## 旧订单发货用时修复

部分旧订单已有可显示的下单时间，但缺失 `orderDatePrecision`，旧采集逻辑又因来自详情而永久跳过补查，导致发货用时显示“—”。后台 3.1.37 允许对缺失或 unknown 精度的详情订单重新补查，保留每轮预算、24 小时冷却和指定订单刷新行为，并兼容合法的非补零日期时间。

只有平台返回明确年月日与时分/秒后才恢复精度及用时。不根据旧数字时间戳反推精度，不把同步时间作为下单时间；平台未返回原始时间的历史订单仍保持未知。

## 升级

1. 拉取 `ghcr.io/zsdd2/kdyzm:3.1.37` 或 `ghcr.io/zsdd2/kdyzm:latest`，保留原数据卷、加密密钥和配置，重建容器。
2. 通过“我的 → 检查更新”，或 [App 3.1.41 Release](https://github.com/zsdd2/kdyzm/releases/tag/app-v3.1.41) 下载原签名 APK 覆盖安装。不要先卸载。
3. 同步已有账号或刷新订单，等待平台补齐旧订单时间证据。

App 版本为 **3.1.41 / 30141**，后台 **3.1.37**，插件仍为 **1.2.0**。无数据库迁移、清库或重新绑定，兼容没有订单的独立取件码。发布后台镜像不会自动替换已运行的 NAS 容器。
