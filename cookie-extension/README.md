# 取件助手 · Chrome 登录同步插件 1.1.2

支持淘宝、拼多多、京东。一个角色授权即可管理该角色的平台登录信息，插件内分别选择同步的平台；也可以先在浏览器登录，再从插件发起授权，首次批量同步自动创建后台尚未添加的平台账号。

1.1.2 兼容京东使用 `light_key` 的桌面网页登录，同时保留 `thor` 支持和 `pin/pt_pin` 一致性检查。接口地址查询缺少必要字段时，会补查已授权平台域，并按原请求的域名与路径筛选；字段冲突仍停止同步。诊断区分浏览器未返回、过期、分区、其他存储区、空值及范围不匹配，不包含 Cookie 值、账号值或其摘要。

## 安装或更新

1. 解压插件至固定目录，Chrome打开 `chrome://extensions/` 并开启开发者模式。
2. 点击“加载已解压的扩展程序”，选择含 `manifest.json` 的目录。
3. 已安装旧版时，将1.1.2的全部文件覆盖至原目录，在扩展管理页点击重新加载。保持目录位置不变，已有配对保存在原Chrome配置中，不必卸载插件。

角色授权和反向同步要求后台3.1.19或更新版本。旧单账号授权仍兼容后台3.1.18；仅更新插件不能给旧后台增加新接口。插件不通过Chrome账号云同步配对数据。

京东 `light_key` 登录方式需要后台 **3.1.20或更新版本**；旧后台仍会以缺少 `thor` 拒绝。更新后台需拉取新镜像并重建容器，普通重启不会更新镜像。

## 推荐：先登录平台，再授权给后台角色

1. 在后台建立角色即可，不必逐个平台填写Cookie。
2. 在插件“从浏览器发起授权”填写后台HTTPS地址，选择要同步的淘宝、拼多多、京东。
3. 点击各平台的“打开登录页”，在此Chrome配置中正常登录。拼多多使用网页版订单登录；只登录手机App不会让电脑浏览器获得登录信息。京东使用网页版订单登录，单独手机Cookie不适用。
4. 点击“读取登录并发起授权”，按Chrome提示授权后台与所选平台。此时后台只收到浏览器名称和平台清单，不会保存Cookie或创建平台账号。
5. 打开后台授权页，正常登录后台并选择角色，点击“授权给此角色”。插件不需要管理员密码，后台不会自动批准请求。
6. 返回插件，点击该角色的“读取并核对已选平台”，核对角色、平台和脱敏账号后一次确认同步。后台缺失的平台账号会自动创建；已有账号仍需身份一致。某个平台失败会单独提示，其他成功项保留。
7. 需要后续自动更新时，再开启对应平台的自动同步开关。

反向请求十分钟有效，批准后仅能领取一次授权。网络中断导致授权结果未收到时可重新发起；新角色配对会撤销该角色原插件授权。请求中的平台选择只决定当前同步选择，角色授权范围包括该角色当前及未来支持的平台账号。

## 另一种方式：后台生成一个角色配对码

在后台“账号授权”选中角色，点击角色操作区“插件同步授权”，生成并复制一次性配对信息。粘贴至插件“粘贴后台配对信息”，核对角色并确认。插件会列出该角色的账号及尚未添加的平台，勾选要同步的项目并授权站点，然后批量读取核对、确认同步。每个平台不需要单独生成配对码。

角色里以后新增的平台账号也会显示，默认不勾选、不上传。一个角色若有同平台多个账号，插件会分别列出，切勿同时勾选不同身份；后台拒绝用同一浏览器登录覆盖另一账号。缺失平台才会自动创建；并发期间已出现账号则提示刷新，不猜测该覆盖哪个账号。

原“账号详情 → 浏览器 Cookie 同步”单账号配对继续可用。角色授权与App的“整组授权”互相独立。

## 自动同步与账号隔离

- 自动同步默认关闭。开启后约三十秒合并Cookie变化，并每五分钟补查；Chrome退出或休眠会延迟执行。
- 取消勾选平台立即暂停其读取和后续上传，并关闭自动同步。已由后台接受的采集任务仍遵循账号的原有调度规则。
- 浏览器身份必须与目标账号一致；缺少标识、冲突或切换账号时停止上传，不推测角色。拼多多需要网页登录信息及 `pdd_user_id/pdduid`，淘宝使用 `unb`，京东使用 `pin/pt_pin`。
- 后台将账号转移角色后，旧子授权立即失效；移回也须重新选择与核对。插件或后台均可撤销整个角色授权，最长九十天后需重新配对。
- 同一Chrome配置通常只保持一个平台的当前登录身份。不同家人同时使用同一平台时，请分别使用Chrome用户配置文件。
- 上传成功代表信息已保存，实际登录有效性以后台采集结果为准。验证码、风控、退出登录或过期仍需本人重新登录，不承诺永久免登录。

## 数据和权限

仅按操作申请后台和所选平台的站点权限，无网页内容脚本，不接受普通网页发出的同步指令。插件只保存角色/账号摘要、独立授权令牌、选择开关、请求状态及Cookie摘要，不保存管理员密码或Cookie原文。授权令牌仅允许角色内同步，不可读取订单或使用管理员接口。

Cookie在内存读取，通过HTTPS提交配对后台并加密存储；只有本机开发测试允许loopback HTTP。请求不跟随重定向。反向请求的领取密钥不会放进后台URL；后台只在管理员明确确认后绑定角色。首次预览仅保存哈希证明，确认后才保存Cookie或创建账号。

开发验收使用临时后台、独立浏览器配置和合成HttpOnly Cookie，没有读取真实平台会话。Chrome原生权限提示需要本人点击；真实账号风控与长期有效性仍需实际使用验证。
