# 取件助手 · Chrome 登录同步插件 1.2.0

支持淘宝、京东、拼多多。新版按已确认的简洁界面收拢为「绑定后台 / 反向授权」，共用后台地址、平台选择、首次账号核对与同步结果。主页只保留角色、平台状态和必要操作。

## 安装与原目录升级

新用户将 `cookie-extension-1.2.0.zip` 解压到一个不含版本号的固定目录，在 Chrome 的 `chrome://extensions/` 开启开发者模式，点击「加载已解压的扩展程序」，选择直接包含 `manifest.json` 的目录。

已有用户无需卸载或再加载一份插件：

1. 从[插件发行页](https://github.com/zsdd2/kdyzm/releases/tag/cookie-extension-v1.2.0)下载 `cookie-extension-updater-1.2.0.zip` 并解压。
2. 双击 `Update-CookieExtension.cmd`，首次选择 Chrome **当前已加载的原插件目录**；更新器会记住它。
3. 结束正在进行的同步，核对当前版本、目标版本与目录，输入 `UPDATE`。工具校验文件并备份，失败回滚。
4. 从1.1.3升级后在 `chrome://extensions/` 点击原插件的重新加载；以后也可使用插件「设置 → 本地覆盖更新 → 重新加载插件」。原目录和扩展实例不变，原角色授权、平台选择、自动同步开关保留。

这是「工具覆盖 + 重新加载」的本地升级。更新器不运行常驻服务、不修改系统执行策略，也不读写 Chrome 配置。策略阻止 PowerShell 时需由系统管理员处理。详细校验、备份和恢复步骤见更新工具包内的 README。

角色授权要求后台3.1.19或更新版本；京东 `light_key` 登录要求后台 **3.1.20或更新版本**。旧单账号授权仍兼容后台3.1.18。本次无需更新已经是3.1.20的后台，App维持3.1.22。

## 共用后台地址

首次「添加授权」时保存后台 HTTPS 地址，后续两种方式都沿用。已有安装从旧授权记录恢复地址；多个后台分别保留，可在主页切换。暂时无法连接时保留角色与历史状态。更换地址不迁移授权令牌，也不会把旧 Cookie 发给新后台。

浏览器名称可在设置中修改，用于后台识别本次申请，不需要管理员密码。

## 绑定后台

1. 后台「账号授权」选中角色，在「插件同步授权」生成并复制配对信息。
2. 插件「添加授权 → 绑定后台」，粘贴信息或配对码。
3. 核对目标后台与角色，选择本次同步的平台。首次不预选，同平台多个账号只能选一个目标。
4. 按 Chrome 提示授予所选站点权限。已核对账号直接同步；新账号集中显示脱敏身份，确认归属后再上传。
5. 成功项先完成，缺登录的平台单独显示「去登录」，不会阻止其他平台。

旧单账号配对信息使用同一入口，只获得其实际平台权限。角色以后新增的平台账号默认不选择、不上传；缺失平台在首次确认同步时建立。并发出现其他账号时停止并提示重新核对，不猜测目标。

## 反向授权

1. 在同一个 Chrome 用户配置中登录所需平台，也可在授权后补充登录。
2. 插件「添加授权 → 反向授权」，选择淘宝、京东、拼多多中的所需平台并发起申请。缺登录不会拦截整份申请。
3. 后台授权页自动打开；管理员正常登录后台，明确选择或新建角色并批准。批准前申请只包含浏览器名称和平台清单，不发送平台 Cookie。
4. 返回插件，显示获批角色并检查所选平台。新账号仍须集中核对一次；成功与待处理项分别显示。

等待申请可在重新打开插件后恢复；有效期十分钟，过期不会删除原有角色或后台地址。领取授权只能进行一次，网络中断导致领取结果丢失时重新发起。新角色配对会撤销该角色原插件授权。后台必须由管理员明确批准，插件不猜测角色。

## 登录补救与日常同步

主页「同步所选平台」统一处理所选账号。需要登录时才显示登录按钮，点击后打开平台官方页面；返回插件或登录 Cookie 变化后只重新检查待处理平台，已成功的平台无需重复操作。首次新身份仍等待确认；不同身份停止上传，不自动替换。

关闭同步流程会取消后续检查与上传；已经被后台接受的请求无法撤回。权限拒绝、网络失败、账号冲突分别显示下一步，诊断默认折叠且不含 Cookie 原值。

「已同步」代表登录信息已保存；「等待采集验证」和「后台最近采集成功」分别展示，不把上传成功当作平台会话已经有效。验证码、扫码、风控、退出或过期仍需本人处理。

## 管理平台与自动同步

- 平台选择和逐平台自动开关统一收在「管理平台」，自动同步默认关闭，旧用户的开关原样保留。
- 首次账号核对后才可启用自动同步。开启后约三十秒合并 Cookie 变化，并每五分钟补查；Chrome退出或休眠会延迟执行。
- 取消选择立即暂停该目标的读取和后续上传，并关闭自动同步。已由后台接受的采集任务仍按原调度处理。
- 一个 Chrome 配置通常只保持一个平台的当前身份。不同家人同时使用同平台时，请分别使用 Chrome 用户配置。
- 账号转移角色后旧子授权失效；移回仍须选择并核对。插件或后台可撤销角色授权，最长九十天后需重新配对。

## 京东与拼多多兼容

保留1.1.2的京东桌面 `light_key` / `thor` 支持与 `pin/pt_pin` 一致性检查。保留1.1.3的拼多多 HTTP/HTTPS Cookie 权限修复：部分登录令牌带 Secure，账号标识不带，Chrome需两种站点权限才能完整读取。HTTP权限仅用于浏览器 Cookie 访问检查，平台和后台请求仍走 HTTPS。

拼多多支持 Chrome 开发者工具的平板模拟模式；需在同一配置的网页完成登录，只有手机App登录不足以让电脑获得会话。诊断区分未返回、过期、分区、其他存储区、空值和范围不匹配，不显示账号值或摘要。

## 数据与验证边界

仅按操作申请后台和所选平台权限，无网页内容脚本，不接受普通网页同步指令。插件本机只保存角色/账号摘要、独立授权令牌、选择开关、待处理请求及 Cookie 摘要，不保存管理员密码或 Cookie 原文，也不通过 Chrome 云同步配对数据。

Cookie在内存读取，通过HTTPS提交配对后台加密保存；只有loopback开发测试允许HTTP。请求不跟随重定向。角色授权不能读取订单或调用管理员接口；反向领取密钥不进入后台URL，首次预览只保存哈希证明。

开发验收使用临时后台、独立 Chrome 配置和合成 Cookie。Chrome 原生权限提示仍由本人点击；真实账号风控、长期登录有效性以实际平台和后台采集结果为准。
